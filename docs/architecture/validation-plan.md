# 验证计划

> 状态：`0.4.1` 已完成验证
>
> 更新日期：2026-09-11

## 1. 权限

- Manifest V3。
- 只有 `storage`、可转债路径 `https://www.jisilu.cn/web/data/cb/*` 和数据板块 SPA 过渡路径 `https://www.jisilu.cn/data/*`。
- 不申请其他权限。

## 2. 橙色 `+`

- 每条已渲染记录的深蓝色 `+` 旁只出现一个橙色 `+`。
- 本地 `+` 与原站 `+` 使用同一 `jisilu-iconfont`、`U+E61E` 字形和 `13×13px` 尺寸，只改变颜色。
- 点击橙色 `+` 后，只保存当前行的代码、名称和添加时间。
- 保存成功后变为红色 `-`。
- 保存成功后，当前行转债名称保持页面原本颜色。
- 连续点击不会生成重复记录。
- 保存失败时保持橙色 `+`，转债名称保持页面原本颜色。

## 3. 红色 `-`

- 点击红色 `-` 后，只删除当前转债的本地记录。
- 本地 `-` 与原站 `-` 使用同一 `jisilu-iconfont`、`U+E61D` 字形、`13×13px` 尺寸和红色 `#dd1817`。
- 删除成功后恢复为橙色 `+`，转债名称继续保持页面原本颜色。
- 删除失败时保持红色 `-`，转债名称保持页面原本颜色。

## 4. 刷新与持久化

- 页面刷新后 `+`、`-` 状态正确恢复。
- 页面刷新、表格刷新和浏览器重启后，无论是否加入本地自选，转债名称都保持页面原本颜色。
- 表格手动刷新后按钮不重复，状态正确恢复。
- 页面内从可转债切到封闭基金时，不在封闭基金表格注入本地按钮；再切回可转债后，每行按钮和已选状态正确恢复。
- 页面内从可转债切到债券时，不在债券表格注入本地按钮；再切回可转债后，每行按钮和已选状态正确恢复。
- 浏览器重启后状态正确恢复。

## 5. 边界

- 不修改集思录原 `+`、`-` 的行为和样式。
- 不修改可转债名称、代码和其他表格字段样式。
- 不主动请求集思录接口。
- 不保存代码、名称和添加时间以外的数据。
- 不出现批量操作、持仓、抽屉、表单、备注或管理页面。

## 6. 待购与本地组合筛选

- 本地自选行的名称后只出现一个灰色 `+` 或橙色“待购”；非本地自选行不显示待购入口。
- 点击灰色 `+` 后保存待购，点击“待购”后直接清除且本地自选保留；不显示确认框或撤销提示。
- 移出本地自选时同步清除待购，不产生孤立待购记录。
- 插件双按钮筛选组只出现一次，位于原站“仅看自选／仅看持仓”按钮组之后、“显示已拉黑”之前。
- 关闭态为白底灰边，开启态为橙底白字，`aria-pressed` 与状态一致。
- “仅看本地自选”和“仅看待购”互斥，并分别显示对应集合与站内当前结果的交集；关闭后恢复全部当前站内结果。
- 与站内筛选取交集，不修改原站“仅看自选／仅看持仓”和“显示已拉黑”的状态。
- 开启期间移出可见记录后该行立即消失；表格排序或重渲染后筛选继续生效。
- 没有匹配行时显示“当前筛选条件下暂无本地自选”。
- 待购没有匹配行时显示“当前筛选条件下暂无待购可转债”。

## 7. 真实页面验证

1. 确认 browser-skill 扩展已连接测试用 Chrome，`bsk status` 显示一个可用浏览器。
2. 插件源码改动后，先在 Chrome `chrome://extensions` 对本项目未打包扩展执行“重新加载”。E2E 使用浏览器当前已加载的版本，不会自动从仓库重新加载扩展。
3. 在仓库根目录运行 `node tools/e2e-cb-list.js`。脚本必须遵循 `bsk session start` → 轻量初始页 snapshot → 打开目标页并验证 → `bsk session stop` 的生命周期；异常路径也必须停止 session。
4. 自动验收只选择初始为本地未选状态的行，结束前恢复其原状态，不得删除已有本地自选。Chrome 进程重启场景仍由手工验收完成，脚本只验证页面刷新、表格重渲染和 Agent Window 重建后的持久化。
5. 把验证方式与结果记录到 `ROADMAP.md`；全部通过后才能标记完成。

## 8. QDII 三表验证

- 欧美市场、商品、亚洲市场分别只注入一个“仅看本地自选”复选框，且紧邻各自站内“仅看自选”的右侧。
- 每条 QDII 数据行只注入一个本地按钮，位于站内按钮右侧；操作列扩宽后两个按钮不重叠、不越界。
- 站内按钮从 `addOwnedQd(...)` 切换为 `delOwnedQd(...)` 并整体重写操作单元格后，本地按钮应自动补回，两个 `-` 仍独立显示。
- 三类可以独立加入、移出和恢复记录；同一代码的唯一语义包含分类。
- 开启欧美市场筛选不得隐藏商品或亚洲市场行；商品和亚洲市场同理。
- 从 `#qdiie` 切到 `#qdiia` 时不扫描隐藏的欧美与商品表，切回后各自状态恢复。
- 页面刷新后本地自选记录恢复，三个筛选复选框默认关闭。
- 自动验收运行 `node tools/e2e-qdii.js`，异常路径也必须恢复测试记录并关闭 browser-skill session。
- 三张 QDII 表均不得注入 `a.jd-purchase-btn`。

验收结果：2026-09-07 运行 `node tools/e2e-qdii.js`，32/32 通过。欧美与亚洲可用数据完成行交互验证；商品表在游客状态只显示登录提示，因此验证筛选控件、零数据边界和无待购入口，不把站点未提供的数据行误判为插件故障。测试记录已恢复，Agent Window 已关闭。
