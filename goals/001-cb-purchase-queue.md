# Goal 001：可转债待购清单与组合筛选

> 状态：已完成
>
> 创建日期：2026-09-07
>
> 完成日期：2026-09-07
>
> 适用范围：仅集思录可转债列表，不包含 QDII

## 1. 目标

在现有可转债本地自选之上增加轻量的“待购”子状态，让用户能把本地自选中的可转债标记为待购买，并在当前集思录筛选结果中快速只看本地自选或待购项目。

该功能只解决“下一步准备购买哪些可转债”的临时清单问题。完成后，用户无需进入独立管理页面即可在列表中标记、识别、筛选和清除待购状态。

## 2. 边界

### 允许做什么

- 待购只作为可转债本地自选的子状态；未加入本地自选的转债不能直接标记为待购。
- 本地自选且尚未待购的转债，在“转债名称”旁显示低强调度的灰色 `+`；悬浮提示明确为“标记为待购”。
- 点击灰色 `+` 后，将该转债加入本地待购清单，并把名称旁的入口切换为橙色“待购”标记。
- 点击“待购”标记后直接清除待购状态并恢复灰色 `+`，不弹确认框，不显示撤销提示。
- 清除待购状态只影响待购清单，转债继续保留在本地自选中。
- 从本地自选移出一只处于待购状态的转债时，同时清除其待购状态，不允许产生脱离本地自选的待购记录。
- 在原站“仅看自选／仅看持仓”筛选组之后增加一个插件自有筛选组，组内并列“仅看本地自选”和“仅看待购”，整体位于“显示已拉黑”之前。
- 插件筛选组复用原站相邻筛选组的尺寸、边框、圆角、字号和选中态视觉，但保持独立 DOM、状态和事件，不进入原站 Vue 管理的组件内部。
- 两个本地筛选互斥：默认均关闭；点击其中一个只启用该筛选；点击当前已启用项恢复为均关闭。
- “仅看本地自选”显示“站内当前结果 ∩ 本地自选”；“仅看待购”显示“站内当前结果 ∩ 待购清单”。
- 页面刷新、表格重渲染、SPA 切换离开再返回可转债，以及浏览器重启后，待购数据和可见标记正确恢复；两个筛选按钮在页面完整刷新后默认关闭，延续当前筛选状态不持久化的规则。

### 禁止做什么

- 不把标记放在正股名称旁，避免被理解为待购买正股。
- 不记录“已购买”、购买日期、数量、价格、成本、持仓或收益；点击“待购”只代表从待购清单移出，不能作为成交记录。
- 不增加弹窗、抽屉、管理页面、确认步骤、撤销提示或完成历史。
- 不主动请求集思录或第三方接口，不读取或保存行情字段。
- 不改变集思录原有筛选、按钮和事件，不改动 QDII 三类本地自选功能。
- 不为本 Goal 引入第三方运行时依赖或新增扩展权限。

### 影响范围

- 数据层：新增可转债待购集合，并维护“待购记录必须属于本地自选”的数据约束。
- 页面适配层：识别转债名称挂载点、注入待购入口与插件自有双按钮筛选组、应用两类互斥筛选。
- 主逻辑：连接本地自选、待购状态、跨标签页同步、重渲染恢复和筛选联动。
- 文档与测试：同步产品、数据、交互、架构、验证、README 和 ROADMAP；补齐单元测试与真实 Chrome E2E。

## 3. 测试

### 单元测试

- 数据层覆盖：加入待购、重复加入幂等、清除待购、非本地自选拒绝加入、移出本地自选时级联清除待购、存储失败时不产生孤立或半完成状态。
- 页面适配层覆盖：灰色 `+` 与“待购”标记切换、同一行不重复注入、名称挂载点失效保护、筛选组位置与双按钮状态、两类筛选结果及空状态。
- 主逻辑覆盖：点击联动、互斥筛选、当前筛选下增删状态、`storage.onChanged` 跨标签页同步、表格重渲染与 SPA 返回后的状态恢复。
- 回归覆盖：现有可转债本地自选和 QDII 三分类本地自选测试全部继续通过。

运行命令：

```bash
node --test
```

### 真实 Chrome 验证

重新加载未打包扩展后，使用项目既有 browser-skill 流程连接真实 Chrome，在可转债页面验证：

1. 本地自选行显示灰色 `+`，非本地自选行不显示待购入口。
2. 点击灰色 `+` 后出现“待购”，刷新页面及表格后仍能恢复。
3. 点击“待购”后直接恢复灰色 `+`，无弹窗、无撤销提示，本地自选保持不变。
4. 两个插件筛选按钮处于同一独立分组，位置、尺寸和状态与相邻原站控件协调。
5. 两个插件筛选互斥；开启“仅看待购”后清除某行待购状态，该行立即消失。
6. SPA 离开可转债再返回后，入口、标记和筛选组各只出现一次，状态正确。
7. QDII 三张表的按钮、筛选、存储与既有 E2E 结果不受影响。
8. 验证结束前恢复自动化产生的本地自选和待购测试数据，并关闭 Agent Window。

真实页面命令沿用并按功能扩展现有脚本：

```bash
node tools/e2e-cb-list.js
node tools/e2e-qdii.js
```

## 4. 验收标准

- 本地自选且未待购的可转债每行恰好有一个灰色 `+`；已待购时每行恰好有一个“待购”标记；非本地自选行不存在待购入口。
- 点击灰色 `+` 一次后只生成一条对应待购记录；重复扫描和跨标签页同步不产生重复记录或重复 DOM。
- 点击“待购”一次后待购记录被清除，本地自选记录仍存在；页面不出现确认框或撤销提示。
- 任一待购记录都能在本地自选集合中找到对应代码；移出本地自选后两处记录均不存在。
- 页面顶部恰好存在一个插件自有筛选组，组内恰好有“仅看本地自选”和“仅看待购”两个按钮；任何时刻最多一个处于启用状态。
- 两种筛选均只作用于站内当前结果，不改变原站筛选状态；没有匹配行时显示与当前筛选语义一致的空状态。
- 页面刷新、表格重渲染、SPA 往返和浏览器重启后，持久化状态恢复正确，且不产生重复入口或筛选组。
- QDII 功能没有待购入口，既有三分类数据和筛选行为不变。
- `node --test` 零失败；可转债与 QDII 真实 Chrome E2E 均零失败，且测试数据已恢复、Agent Window 已关闭。
- Manifest 权限无新增，运行时依赖无新增，插件不产生外部网络请求。
